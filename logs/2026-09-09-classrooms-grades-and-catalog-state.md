# 教务查询、课程身份与目录状态排查

## 教室协议

真实本科门户的教室信息查询表单 POST 到 `/jsxsd/kbxx/jsjy_query2`。`jc/jc2` 使用 `01` 至 `12`，状态为空时返回占用矩阵。全天结果表 `#dataList` 首行是星期，第二行的 `tdvalue` 为 `0102 / 0304 / 05 / 0607 / 0809 / 1011 / 12`；这是观察到的样本，解析器按实际列值展开，不能写死分组。

教室行带 `jsbh`，空单元格表示空闲，`◆ / Ｊ / Ｘ / Κ / Ｇ / Ｌ` 等已知符号表示占用。表头并无“教室”字样。以该字样强行验表会拒绝正常响应；把异常逐节转成 unknown 又会将整体失败伪装成成功。不要根据“未出现在空教室名单”推断目标被占用。一次全天请求即可供占用查询，避免 12 个并发请求争用同一教务会话。

补充排查发现真实页面同一单元格可以同时显示 `◆` 和 `Ｊ`。解析必须按已知符号组合判断，不能把整个字符串与单个符号列表做相等匹配；全半角、空白、换行和嵌套标签不得改变判定，未知内容仍需显式报错。按节次会检查多个教室，因此单格识别失败可以造成整次查询失败，而单教室查询可能恰好不受影响。

空结果提示必须绑定查询条件。“按教室”查询完成后切到“按节次”，若共用已查询布尔值而未清除，就会在未查询时错误显示“没有可用教室”。请求身份也必须独立于条件身份，避免切换条件后再切回来时接受旧响应。

## 成绩和培养要求

教学执行计划和成绩表都有课程编号。真实对照中，全部成绩 91 条、最好成绩 89 条、唯一编号 89 个；按编号取最好成绩与学校每条记录一致。同名同学分但不同编号的体育、形势与政策等是独立课程，不能作为重修合并。

该次学校官方所得学分与逐门通过课程求和不同；来源口径尚不能仅凭成绩明细解释。应保留官方数值与来源，其他计算注明估算，不调整常量凑数。培养方案说明第二课堂不列入毕业总学分，仍属于必修课外要求。专业配额来自当前用户方案，样本专业及其学分不得进入生产常量。

官方学分汇总有 rowspan/colspan，多级专业选修/公共选修表头需展开后识别。不能在整页展平文本上宽松匹配“学分积”后任意数字，这会误取排名表的序号或年份。文字等级没有可靠学校换算规则时不转为 95/85/75。

## 页面状态

评价容器 switch 会销毁子视图 @State，而父级首次加载标记仍存活；因此切回时空列表与已加载标记矛盾。数据与加载状态需由同一个稳定所有者持有，且仅成功标记完成。

跨 Tab 路由可能先于 SwiftUI 的 selectedTab onChange 被消费。随后无条件清空 NavigationPath 会抹掉刚打开的目的地；按路径所属 tab 判断是否应清空，快捷菜单动作在消失回调后执行。
