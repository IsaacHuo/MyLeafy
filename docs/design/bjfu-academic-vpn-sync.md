# 北林本科非校园网教务同步

跟踪：[#79](https://github.com/IsaacHuo/MyLeafy/issues/79)，接入验证 [#80](https://github.com/IsaacHuo/MyLeafy/issues/80)。

## 产品约定

目标是使用流量或普通 Wi-Fi 时，也能在 App 内手动更新教务数据，包括人在校内但未使用校园网的情况。配置 VPN 后默认由服务器代连北林，校园网直连仅作为用户选择的本次兜底；不检测网络后自动改变优先级，不定时同步，背景预取不建立 VPN。

入口为「我的 → 缓存与同步 → 教务连接」，配置项为「北林 VPN 同步 · 推荐」。凭据仅在用户主动选择时保存于 Keychain / Keystore，并与教务凭据分开。支持非校园网首次登录和校园网登录后引导配置。失败保留上次成功数据，并提供重试、修改配置和本次校园网直连。

先完成双端本科课表并真实验收，再覆盖两端已有的其他本科教务功能，之后准备双端新版。研究生、其他学校和定时更新不在本轮范围。现有两端学期、解析及本地数据保护语义保持。

## 2026-11-10 接入验证

实际目标为当前 ECS。Ubuntu x86_64 上生产和 staging 服务保持运行，强智首页、登录密钥和验证码的直接请求均超时；VPN 网关 HTTPS 可达，报告 EasyConnect `M7.6.8R2`。

使用所有者提供的本人凭据，已验证以下完整链路：

1. HTTPS 登录学校 VPN，得到明确的 `Result=1` 和授权资源列表；列表包含 `newjwxt.bjfu.edu.cn`。
2. 沿学校门户自身 JavaScript 的转换规则，经 `/web/1/http/0/newjwxt.bjfu.edu.cn/` 读取强智登录页、有效密钥和 JPEG 验证码。
3. 在同一操作中按强智协议编码并提交教务登录；以会话验证页的明确认证内容确认成功。
4. 收到 54,015 字节课表页面，页面选择项证明来源学期为 `2026-2027-1`。98 个 `kbcontent` 容器只是 HTML 结构计数，不代表课程数量或解析验收。
5. 向学校 VPN 发送 POST 退出，收到明确成功的 `ErrorCode=1`。

认证材料通过一次性加密桥传递，Cookie 与凭据仅留在临时操作内存；不输出或持久化学校页面、密码、Cookie。验证服务仅监听 ECS 回环地址，设置内存、禁用交换、禁用 core dump 和最长运行期限。原默认路由和既有服务运行状态检查保持。没有修改 Caddy、生产配置、数据库或移动端。

本次先尝试本机 Vision 的原图、四倍放大、灰度增强三路识别，沿用两路一致且最低置信度 0.85 的限制；一次提交被学校明确判为验证码错误，后续低置信度没有提交。最终成功使用人工核对的验证码，不算自动识别成功。

另验证过用户态 EasyConnect 客户端候选，其严格证书验证下的专有隧道失败，没有采用跳过验证的方式。它未成为项目依赖，候选二进制和临时进程需随验证环境清理。当前采用学校原生 HTTPS 网页 VPN 作为后续实现基础，不需要在业务宿主机安装 EasyConnect 或改变默认路由。

依据：[学校 VPN 服务说明](https://nic.bjfu.edu.cn/bszn/bslc/c5e6826b4e424db886eb70b0780de781.htm)、[学校门户资源转换脚本](https://vpn1.bjfu.edu.cn/portal/jssdk/business/res_opener.js)。学校说明中「教务系统不需要 VPN」不替代当前 ECS 的实际连通性结果。

## 本阶段工程验证
