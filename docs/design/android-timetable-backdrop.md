# Android 课表背景贯通

课表启用照片或纯色背景后，原先独立的顶部、节次列和底栏遮住背景，形成分割。本轮将背景画布提升到根导航外壳，顶部与节次列透出同一背景，底栏保留圆角、布局与选中圆底，降低表面、描边和阴影强度。关闭背景时维持原有默认画面。

## 实现与边界

`MainActivity` 从已有 `SettingsStore` 收集设置，经 `MyLeafyApp`、`MyLeafyNavHost` 向导航外壳与课表传递同一背景配置。`TimetableNavigationScaffold` 的背景槽始终保留组合状态；只有课表根目的地绘制背景及轻透导航，其余 Tab 与二级目的地恢复默认表面。

`TimetableBackground` 以当前图片路径为键在 IO 线程采样解码。切换 Tab、进入二级页和跨 600dp 时隐藏绘制，保留解码状态；换照片或关闭背景改变解码键。沿用原有 crop/fit、可见度、模糊与遮罩规则，API 29–30 仍读取已有模糊缓存。整页只绘制一次图片，不拉伸、不在不同区域重复铺图。

`TimetablePageBackdrop` 在同一整页画布上绘制顶部、左缘和底部的主题色渐变。顶部保护区随系统栏和字号调整；左缘贯通整页，避免节次首尾出现矩形切口。`TimetablePageScaffold` 只在背景启用时使用透明容器与顶栏。详情 Sheet、菜单及对话框继续使用独立表面。

底栏轻透表面在浅色为 42%、深色为 56% 不透明度，描边为 12%，取消阴影；保留原圆角、导航占位及选中圆底。Navigation Suite 的 Rail 和横屏自适应底栏同步应用表面规则。布局 Insets、13 节累计像素几何、固定左轴和翻周逻辑保持原有职责。后台投影、Room v9、API、身份隔离及设置存储格式不变。

所有截图使用固定本机图片与测试数据。完整系统栏截图来自实际 `MainActivity`；连续反向翻周与下拉同步保留录屏。开发机资料位于 `android/app/build/timetable-backdrop-20261009/`：`comparison.html` 为可点击原图的前后对照，`before/` 与 `after/` 保存图片，`native-full-page.png` 保存实际系统栏画面，`paging.mp4` 保存交互，`native-*.txt` 保存测试结果。

Gradle 使用有界工作流输出。验证中的编译输入类型问题已修正为校园时区 `ZonedDateTime`；Robolectric 的 PixelCopy 无法完成颜色采样，因此解码生命周期证明放到原生模拟器执行。记录截图后的完整验证独立运行；没有以录图成功代替视觉检查。

## 交付与现场验收

版本配置提高到 1.2.4/code 8；已有私有 1.2.3/code 7 保持不可变。任务分支当前提交的 `CI result` 通过后才能快进主线，再由现有流水线准备私有正式签名候选。正式发布仍通过用户在版本管理页的候选验收与发布操作。

本轮没有安装或清理连接的实体手机，也没有部署后端生产环境。图片压力场景验证的是当前 fixtures 的可读性，不代表所有照片的逐像素对比度认证。API 29–30 真机模糊、TalkBack 阅读、同期 iOS 真机比较与真实学校身份覆盖升级仍需现场检查。当前证据没有测量实体设备帧时，不宣称真机性能或 iOS 同等流畅度。
