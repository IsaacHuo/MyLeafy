# iOS 当前课表与个人数据同步

## 产品约定

课表是固定 20 周的当前排课容器。学校更新排课后完整覆盖旧课程；开学日期和学期标签不影响获取。手动课表刷新只读取本机配置，不等待远程学期 API；远程校历由前台独立刷新。备注、课次备注、提醒与个人日程由用户拥有，不能因学校删除/调换课程而删除。唯一关联继续使用，歧义进入待关联页面；未关联提醒暂停，重新关联后恢复。

时间视图与我的页进入同一课表设置，首周选周一，学年/学期仅显示。用户可设置 1–24 节作息，各节必须有序且不重叠。日期变化保持选中周次，重算课程相关日期；个人日程的明确日期不移动。年度/校历展示不定义课程可用性，容器的 20 周末日不等于学校放假日。

日程菜单导出所有现存历史和未来日程到 Apple 日历或 UTF-8 TXT。日历重复导出更新旧事件，两类导出共用本机事件账本；开学日期移动后仍按已知事件标识更新，格子日程与课表导出共享标识；个人日程另有稳定 ID，不混入学校课程/考试/随记。无结束时间时日历使用已说明的 45 分钟，TXT 不补写时间。找到我使用用户提供的拟我表情原图及指定小红书链接。

## iCloud 设计

默认关闭，用户确认后使用 Apple CloudKit 私有数据库，MyLeafy 服务不经手。每个校园身份独立 zone，游客独立，Demo 禁用。使用 CKSyncEngine 承担传输、订阅与系统重试，显式模型 DTO 和设置 allowlist 连接本地存储；SwiftData 的自动 CloudKit 镜像关闭。

同步课程、成绩考试及成绩补充快照、备注提醒、个人日程、随记及媒体、课表与个性化设置。未纳入的学习资料/项目、职业规划、体测、综素、医疗等保留本机。学校会话及任何凭据不上传。

持久 journal 保存待发送记录、删除标记、接收 inbox、未完成下载重取 ID、系统字段及引擎状态。崩溃后可重放接收，启动时对照已提交数据补齐离线修改和删除；先获取云端再允许发送，禁止空设备覆盖云端。学校数据按成功获取时间选择完整快照；通用/免登录入口的手动成绩按 UUID、手动考试按持久 syncID 逐条合并，个人记录按稳定 ID 合并，文本冲突保留可访问副本。删除标记阻止旧编辑复活记录，设置按字段使用修改时间合并；课表的学年、学期、首周周一与作息独立同步，作息数组整体校验。

文件独立 CKAsset，元数据和大文本负载显式编码，下载验证 SHA-256 后原子替换。暂存失败不推进本地已应用状态；即使系统游标已推进，持久重取 ID 仍能恢复文件。旧身份、退出或 Apple 账号变化均使正在运行的引擎失效。

关闭保留本机/云端数据；清理本机缓存先暂停同步并重置本机同步基线。删除此身份云端 zone 需要独立确认。重新开启会再次合并/上传本机数据。

## 验收边界

本地构建、离线回归、学校实网及真实 iCloud 分开记录。CloudKit 容器需在开发者团队中配置并更新签名 profile；开发 schema 须在正式发布前提升至 production，不能用无签名 Simulator 构建证明服务已可用。必须以同一 Apple 账号的两台设备验收首次合并、离线编辑/删除、文本冲突、媒体、关闭/重开与账号切换；真实本科/研究生还需校园网或 VPN 验收。正式 Apple 发布和 CloudKit production schema 单独确认。

共享快照使用可选 `calendar_config` 携带发布者的首周周一和作息，不使用查看者的日期与时间。D1 0015 为新增可空字段，旧客户端省略时保持原接口；该 Cloudflare 独有字段不加入旧 Supabase 源数据迁移 mapping。后端部署需先应用迁移，生产仍由所有者在 GitHub Actions 审批。

用户缩小节次后拉取到更晚课程时，完整数据保存为当前身份的待导入文件；补全作息后直接导入，无需再次请求学校。暂存不进入 iCloud 或共享，只有提交成功的课程成为可发布快照。

CloudKit development 使用 `PersonalValue` 记录类型，字段为 `value`（Bytes）、`asset` / `payloadAsset`（Asset）和 `payloadDigest`（String）；开发环境首次保存生成 schema，正式发布前需在 CloudKit Console 提升至 production。工程已配置 `iCloud.com.isaachuo.leafy`，仍须以开发者账号核对容器归属和签名 profile。

旧全局个人日程在首次读取时归入当前身份并删除旧键，后续按身份保存。显式重建空数据库保留 iCloud 开关和账号绑定，但清除本机同步基线与游标，先从云端恢复，不能把恢复空库当作用户删除。

## iCloud 初始化与故障定位

Debug 明确使用 `Development`，Release 明确使用 `Production`，由 `LEAFY_CLOUDKIT_ENVIRONMENT` 同时写入 entitlement 和诊断用 Info.plist。验收必须核对签名后的包，而不只检查工程源文件。已有云端 zone 先读取，仅收到 `zoneNotFound` 才创建；权限、认证、服务端拒绝等错误直接保留，不能当作 zone 不存在。

同步页展示当前阶段，并提供只包含错误元数据的诊断信息（阶段、环境、容器、错误码、HTTP 状态、请求编号）；不包含记录正文、凭据或 HTTP headers。服务端或引擎回调失败不能被后续发送步骤清空，也不能据此标记同步成功。无关 UserDefaults 通知在未产生同步数据变更时不触发失败请求重试，手动/前台重试继续可用。

2026-10-16 真机旧包可复现 `CKErrorDomain 15`：私有 zone 的 PCS 获取在中国区网关返回 HTTP 500，随后 `CKDModifyRecordZonesOperation` 拒绝保存分区。失败发生在业务记录上传之前；仅凭错误 15 不能认定是 schema 缺失。修复包需要重新在真机验证该服务端问题是否仍出现，生产 schema 发布与双设备一致性仍单独验收。
