# iOS 产品介绍与密集课表

## 产品表达

MyLeafy 是精致的校园日常工具，介绍页以“把校园工具认真做好”为主线。
“我的 → 了解 MyLeafy”直接展示品牌简介、五个主题封面与版本号。
主题包括每日安排、日迹、校园事务、设计细节、数据边界；点击进入图文详情。
界面示意使用静态 SwiftUI 组合，不读取个人数据、不初始化业务服务、不写入数据库。
帮助中心继续负责操作说明，介绍页负责解释产品与设计选择。

## 密集课表规则

- 课程、格子日程、个人日程和考试共享一套冲突投影。时间端点来自课程节次或记录的真实起止时间，沿用现有时间轴映射。
- 以起止时间划分区段，冲突组内分配稳定车道；区段内把空闲车道空间分给仍在持续的项目。安排持续跨区段时车道锚点不变。
- 同时出现两至三项时并列；四项及以上仅汇总拥挤区段。数量按项目 ID 去重，点开显示该区段的全部项目。
- 项目的非拥挤部分形成连续阶梯轮廓；跨越汇总区段时显示为多个可见部分。任一可见部分进入同一记录，凹口不接受该记录的点击。
- 主文字使用高度足够的最宽内接矩形，同宽时选较早的位置。标题优先，按空间依次显示课程备注或地点及辅助时间，不按字符数提前截短备注，不把字体持续缩小。
- 窄段使用轻量类型图标。课程长按仍可读取完整备注；列表中的标题、地点和备注不截断。
- 缺少有效考试结束时间时保留短视觉标记，不在文字中虚构结束时间。屏幕外时间范围仅裁切显示，不修改记录。
- 投影按日缓存，身份包括课程/备注/格子日程快照、个人日程/考试签名、日期、语言和节次数量。周与三日模式只改变几何，不在缩放帧重新分配冲突。

本次不改变 SwiftData、提醒排期、学校同步、Widget、Android 或分享图布局。

## 后续体验审查

用户负责真机视觉验收，本轮按最新要求只做构建与静态检查，不运行模拟器或本地测试。
后续按以下路径收集用户真机画面，再形成有证据的修整清单：

| 路径 | 验收重点 |
|---|---|
| 看课表 → 课程详情 | 课程、日程、考试互不遮挡；备注可读；轮廓点击正确 |
| 新建日程 → 课表与日迹 | 同一记录的时间、标题、编辑结果一致 |
| 写随记 → 搜索与回顾 | 入口清楚；创建、查找、回顾反馈连贯 |
| 校园 → 成绩、考试、教室 | 名称与分组可理解；来源、时间和失败状态准确 |
| 我的 → 了解、帮助、反馈 | 介绍与教程分工明确；支持入口可发现 |

后续问题清单逐项记录画面、用户影响、修改方案、优先级和复验条件。
本轮静态待核验项包括英文/大字体示意的裁切、极短拥挤区段的数量文字和两至三项并列时的触控可用性，不能将其表述为已通过视觉验收。
Android 下载更新已在当前主线使用 Cloudflare 公开发行接口，本任务无需重复安排渠道迁移。
