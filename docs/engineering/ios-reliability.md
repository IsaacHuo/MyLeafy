# iOS 本地数据与异步任务可靠性

本次修复保持功能、导航及视觉结构，沿用 SwiftData、SwiftSoup 和现有服务接口。工程约束的当前实现见 `state/ARCHITECTURE.md`。

## 数据库打不开

默认保留持久库，展示错误并允许重试，不自动重建、不降级到可写临时内存库。用户明确选择新建数据库后，先复制并核对每个存在的 store、WAL、SHM 和待清理文件记录，再删除原组件并打开新库。失败恢复原组件，备份目录保留。个人数据不会自动恢复；旧清理记录随备份归档，避免空库误删原资料文件。

## 保存、文件与发布

模型保存的撤销只针对本次操作，不对共享 context 执行全局 rollback。文件删除记录在数据库提交前落盘，提交后检查文件记录是否仍被引用，再清理；失败保留待办并提示，可跨启动恢复。

学习资料复制使用预分配文件名和稳定记录 ID，复制前持久化清理意图；失败不留下部分资料记录，外部批次可重试。提交后的暂存清理失败属于清理警告，不能诱发重复导入。

发布队列先原子写盘再交接草稿与启动 worker。无法读取的队列禁止覆盖；任务绑定创建身份，其他身份不恢复任务。没有身份归属的旧任务保留原数据，不把它们猜测绑定到当前身份。正式后台接口与幂等 request ID 不变。

## 验证边界

测试使用明确的单测启动标记、空根界面、隔离的 SwiftData/文件目录及注入服务。默认生产传输在测试中拒绝请求。故障回归覆盖备份/保存/复制/清理失败、身份切换、混合异常考试行、发布写盘失败与录音权限迟到。

随记图片、主线程 HTML 解析和上传进度写盘仍是性能候选。此任务没有启动交互走查、ETTrace 或 memgraph；不得将结构变化或单测时间当作帧时、内存或耗电改善。采样获准后，按 Build iOS Apps 对各条单一旅程采集匹配符号的基线与修改结果，并遵守三次运行、中位数改善至少 10%、峰值内存回退不超过 5%、无新增 App 自有泄漏的门槛。
