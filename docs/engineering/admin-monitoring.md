# Admin 与单机监控

跟踪 [#65](https://github.com/IsaacHuo/MyLeafy/issues/65)。本文说明任务源码；生产是否已经部署，以 CURRENT 和交付证据为准。

## 管理与契约

`/admin` 使用 Refine 5、Ant Design 5、React Router 7；官网保留自身样式，后台、监控页面和 ECharts 懒加载。Refine 接管认证及资源查询，服务端继续负责角色、CSRF、审计和业务状态。`admin-action-baseline.json` 固定原有 82 个动作，新增六项监控读取后合计 88 项。

学校范围、排序分页、保存视图、筛选导出、搜索详情、批量操作、上传、未保存确认、主题、三种角色和 Android 发行均保留。新监控仅超级管理员使用；平板使用 Drawer 导航。未恢复 App 行为上报，未修改客户端 `/v1` 业务协议。

## 数据流与权限

Caddy 在落盘前删除 URI、查询、请求/响应头、TLS 和自由错误文本，追加固定路由模板、请求 ID；IP 在源端掩码。Node 再按路由白名单校验，未知路径归为 `/:unmatched`。模板与实际 API 路由的一致性由测试检查。

独立 monitor 读取本环境网关日志、允许的 systemd 单元和内核 OOM/I/O 事件。仅索引结构化白名单字段，不保存自由日志正文。文件偏移和 journal cursor 与入库一起提交；分批补齐并显示积压、错误、覆盖起点和数据过期。监控数据不在业务数据库内。

Prometheus 每 30 秒抓取 host、Caddy、API 进程与 monitor 指标。node_exporter 只启用所需项。API 指标与任务快照使用独立回环监听器，WebSocket 数量来自既有服务器；不消费媒体/下载响应流。主机指标共享，应用与请求以 production/staging 分开标记。

管理查询沿用同源 BFF，经服务端超级管理员校验后，再以独立 token 访问回环 monitor。只接受固定指标和筛选参数，不接受任意 SQL、PromQL、URL、文件路径或 shell；轮询不逐次写入业务审计。monitor 只获取必要的发信配置，不读取完整业务 env 或业务数据库。备份时间和结果由 root 写入独立只读目录。

## 运行与保留

- 回环端口：Prometheus 9090、node_exporter 9100、API 指标 3120/3121、monitor 3140/3141；Caddy 管理仍为 2019。这些端口不得对公网开放。
- 网关日志在 `/var/lib/caddy/myleafy-access/{environment}`，可沿用 Caddy 现有写目录权限，配置 reload 无需新增公开端口。
- 指标保留 14 天，总磁盘目标 1 GiB；块保留 768 MB 给 WAL/head 留余量。访问日志每环境约 128 MiB，每环境 SQLite 硬限制 100 MiB，活跃页达到其 85% 时清理，给 WAL 和整理留余量，两环境日志合计目标 512 MiB、7 天。告警、日报和发送回执保留 30 天。
- 缺失、积压、过期或容量清理必须可见，不能显示为完整或健康。接口统计排除自身探测、健康检查和后台轮询。请求和字节不是活跃用户；长连接在结束后计入。

## 告警与日报

systemd timer 每天北京时间 21:00 生成前一个 21:00 至本次 21:00 的日报。发送账本及服务商幂等键持久化；恢复后只补最近一期缺失报告。初次采集、采集缺口和容量清理均标记范围不完整。收件人只在服务器受保护配置中设置，界面不提供修改入口。

阈值为 CPU 85%/10 分钟，内存 85%/5 分钟，磁盘 85%/5 分钟或 95% 立即；官网/API 连续三次 30 秒探测失败。5 分钟至少 100 请求且 5xx 超过 5%、10 分钟至少 100 请求且 P95 超过 2 秒，同类应用错误 5 分钟十次、OOM、异常退出、任务/备份失败及备份超过 26 小时也触发。首次通知、持续最多每小时提醒一次、稳定恢复五分钟通知。部署/备份使用有限维护窗口。

沿用 Resend，监控最多每日十封；失败保留状态并退避重试，不升级套餐。生产/测试默认关闭真实邮件，验收后才启用生产。服务商额度及真实收信须单独验证，API 接受不等于收件箱收到。云端 ECS 事件邮件独立于本机，限定本实例；联系人激活、策略匹配、启用和送达分别记录，不开通付费采集或拨测。

## 验收与发布

后端完成类型、契约、业务/监控测试；网站完成类型、构建、单元和 Chromium/WebKit/iPad WebKit 流程。staging 演练 API 故障、备份失败、采集器中断与重启续读，再执行至少 30 分钟代表性只读负载。新增常驻内存目标 350 MiB、平均整机 CPU 5%、业务 P95 增幅 5%；未满足前不宣称生产验收完成。

生产消费相同 staging 产物并保留 GitHub 所有者审批。回退可独立停用监控、恢复原界面产物，保留历史目录，不回退业务数据库。实际配置与换机说明同步 Configuration，源码、本地测试、服务部署和真实邮件送达分别记录。
